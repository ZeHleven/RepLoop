# 症状事实改由模型提取：设计方案

版本：草案 v0.1｜2026-11-01｜状态：**待用户确认第 7 节**。评测规范仍为 `15-symptom-scope-eval-spec.md` v1.0，不因本设计改变。

## 1. 为什么要改

留出集 v1（Codex 盲写）上，正则识别器的疼痛题只过了 9/16，而在实现者见过的开发集上是 24/24。失败几乎都出在"理解用户这句话"这一步：方言（"脚脖子"）、声明（"不是说我""我没受伤""膝盖没事"）、单引号转述、追问问法（"考虑""吧""做不做"）、急症词的否定。每补一个词，下一种说法又会漏；而一旦漏判落回旧模型路径，就可能出现试练许可（HP04、HP10、HP14），直接成为红线。

结论：**"听懂"交给模型，"决定"留在服务端。** 模型只输出结构化事实，不写回复；停哪些动作、怎么回复，仍由现有的确定性逻辑完成，"模型不开处方"的产品原则不变。

## 2. 总体流程

```text
用户消息 ─┬─> 意图路由（现有，不改）──────────────┐
          └─> 症状事实提取（新增，与路由并行）──┐  │
                                               v  v
                              服务端校验事实 → 路由决定
                                 ├─ 急症：急救模板（现有）
                                 ├─ 疼痛：确定性取舍与回复（现有 render_reply）
                                 └─ 其他：原链路（现有）
```

两次模型调用并行发出，用户等待时间约等于两者中较慢的一个，和现在基本相同。

## 3. 提取什么（输出结构）

新模块 `agent_symptom_facts.py`，一次严格 schema 调用，温度 0。输出只有枚举、布尔、数字和**用户原文引文**：

| 字段 | 内容 |
|---|---|
| `purpose` | 本轮主要目的，枚举：`own_symptom_training`（本人当前症状并涉及训练，含只陈述疼痛）、`record_query`、`general_knowledge`、`third_party`、`past_resolved`、`no_symptom` |
| `reports[]` | 本人当前症状：`region`（枚举：肩、腕肘、膝、腰背、踝、其他、说不清）、`side`、`quote` |
| `care_signals[]` | 枚举：肿胀、淤青、变形、外伤、无法承重、麻木、无力、静息或夜间痛；每项带 `quote` |
| `clinician_instruction` | 转述的医嘱：`quote`，以及 `restricts_load`（休息、制动、不能负重时为真） |
| `time_cap_minutes` | 每次时长上限，没有为空 |
| `emergency_signals[]` | 枚举：胸痛或压迫、冷汗、呼吸困难、口唇发紫、晕厥或眼前发黑、心律异常、单侧面部或肢体麻木无力、言语不清；每项带 `quote` |
| `continues_previous` / `resolved_now` | 本轮是否在延续上一轮的症状话题；用户是否说已经不疼 |

部位只让模型选**身体区域**，"区域 → 动作"的映射仍由服务端用动作库标注完成（`其他`、`说不清`照旧整份先停）。

## 4. 服务端如何使用（确定性）

1. **校验**：所有 `quote` 必须是本轮或同一症状话题内用户原话的连续子串，否则丢弃该项；字段不合 schema 时整次提取作废。模型不能凭空制造症状或就医信号。
2. **急症**：`emergency_signals` 非空，或意图路由判为高风险，或现有急症词兜底命中，三者任一 → 急救模板。急症只增不减。
3. **疼痛路径**：`purpose = own_symptom_training`，或 `continues_previous` 且上一条助手回复是疼痛路径、本轮没有 `resolved_now` → 用提取出的区域、就医信号、医嘱、时长生成确定性回复（`render_reply` 不变）。
4. **其他目的**（查记录、一般知识、第三方、已恢复、无症状）→ 原链路，与现在相同。
5. **提取失败**（超时、格式不合、服务不可用）→ 退回现有正则识别器，行为与当前版本相同。正则不再是主判断，只做兜底。

## 5. 代价与风险

- **费用**：每条消息多一次小调用（约输入 1.5k、输出 200 token），按保守价约 ¥0.005/条。
- **延迟**：与意图路由并行，预计不增加或略增。
- **模型误判**：用原文引文校验防止编造；用评测规范的 3 遍稳定性检验时对时错；提取结果全部写入运行记录，可逐条复核。
- **提示注入**：输出只有枚举和经过校验的引文，用户文本无法让服务端执行别的动作。
- **两套判断不一致**：开发阶段同时记录"模型提取"和"正则"的结论，统计分歧，作为调试依据；上线只以模型提取为准（失败时才用正则）。

## 6. 实施与验收步骤

1. 新增 `agent_symptom_facts.py`（schema、提示词、调用、校验）与单元测试（引文校验、作废、退回正则）。
2. `decide_scope` 改为接收已校验的事实；运行时把提取与意图路由并行发起。开关 `AGENT_SYMPTOM_FACTS_MODEL_ENABLED`，关闭即回到当前版本。
3. 先跑**提取层开发评测**：用全部开发题（旧 40 实例、探测 20、v1 24、v2 24、留出集 v1 40，共约 150 题）只评提取结果是否符合期望，每遍约 ¥1。
4. 再跑完整开发集真实模型 ×3，达到规范门槛后冻结候选。
5. 用 Codex 已写好、由你保管的留出集 v2 验收（约 ¥2–3）。

## 7. 需要你确认的决定

| # | 决定 | 建议 |
|---|---|---|
| 1 | 每条消息都调用提取，还是先用宽松关键词预筛、只有可能相关时才调用 | **每条都调用**：预筛本身又是正则，会重新引入漏判；费用很低 |
| 2 | 急症判断 | 模型提取、意图路由、急症词兜底三者取并集，宁可多报 |
| 3 | 模型提取与正则结论冲突时 | 以模型为准，正则只在提取失败时兜底 |
| 4 | 本轮开发费用上限 | 提取层评测加完整开发集多遍，合计不超过 ¥8；留出集 v2 验收另计 |
