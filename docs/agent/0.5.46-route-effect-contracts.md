# Align semantic routes with supported effects

The previous candidate passed both CI runs and all 60 daily-meal live tasks, but
its route gate rejected `请记录我接受过膝关节手术`: the model selected
`health/mutation/create`. Three targeted calls reproduced both the create route
and create change. The existing profile proposal service accepts only updates
to existing health fields, so this route could not complete the requested task.

Health writes now explicitly mean updating profile fields. Structured route
validation rejects health create/delete before extracting changes and uses the
existing bounded repair path. It does not silently relabel an operation or grant
write consent. Health reads, risk levels, proposal confirmation and profile
weight-log creation retain their existing contracts.

The route prompt also separates output scope from persistence: daily or multiple
meal planning remains `generation/read/daily_meal_plan` when the user says not to
record it. Single-meal advice remains `query/read/answer`. A previously observed
three-meal/no-record request and a single-meal control were added to the route
gate (33 cases); the three-meal request was added to each daily-meal pass (31
cases, 62 across two passes). Existing cases, thresholds and no-write checks are
preserved.

Local validation: all seven targeted real-model cases match their expected
contracts on the first attempt; all 1803 backend tests pass (807 existing
deprecation warnings). Seven new deterministic cases include rejection of
unsupported health operations and a transport-level repair test that verifies
change extraction only follows the corrected route. The original live failure
and before/after raw responses are retained locally. New-SHA CI, live release
gates, deployment and phone acceptance are tracked separately.
