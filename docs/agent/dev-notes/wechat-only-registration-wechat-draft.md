# 开发笔记：给新账号入口加一道门

本地草稿，未发布。状态：本地446项回归通过，发布包准备中，尚未上线。

给每个账号设5元模型额度后，还有一个问题：如果能不断新建账号，就可以不断获得新额度。

我们沿着体验版登录页面查到服务端。页面主要展示微信登录，折叠区也能用邮箱创建账户；后端同一个注册接口还接受手机号。这里没有邮箱或短信核验，页面的“开发调试”标注也不会限制谁可以调用接口。

用户选择把体验阶段的新账号入口收窄到微信。服务端保留原注册地址，统一返回“邮箱和手机号注册已关闭，请使用微信登录。已有账号仍可登录。”注册请求不会查询账号是否存在，也不会写用户、档案或费用账本。

已有邮箱账号仍然能使用原密码登录，微信第一次登录仍会建号，重复微信登录会复用原账号。原来的消费和预留也保留，不因登录或重新部署获得新额度。旧小程序的创建账户按钮会收到这条关闭提示，本轮不重新发布小程序。

验证使用隔离数据库、合成账号和微信接口替身。已有测试原先借助注册接口准备账号；这部分改成明确的测试夹具，直接创建既有身份，再通过真实登录接口取令牌，没有在产品里留重新开启注册的测试开关。14项新策略测试从修改前13失败/1通过变为14通过；受影响范围最终446项通过。中间一次合并测试进程异常退出，我们保留日志，改用逐文件新进程完成相同范围，未删样本或放宽断言，进程异常根因仍未定位。

实际隔离HTTP回放中，邮箱和手机号两次新注册从201、增加2个用户，变为403、增加0个用户。已有邮箱登录与微信首次/重复登录都保持，原费用余额不变。这些是合成回放，不是生产注册或手机现场；线上结果仍待部署后核验。
