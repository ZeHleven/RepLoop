# 开发笔记：给体验版加上每账号5元的费用边界

状态：本地草稿，未发布；实现与离线验收完成，尚未部署到微信体验版。

这次问题来自一个直接的担心：体验成员如果不断向Agent发消息，会不会持续消耗模型费用？

检查最近交付的代码后发现，我们有限制一次任务的模型调用次数，却没有限制一个账号的累计消费。用户要求很明确：每个人最多用5元。本轮按服务端账号落实，从功能启用时计起，不按天或会话重置。

关键不只是回答结束后加一笔费用。两个请求同时到达时，如果都看到余额充足，再各自发出去，最后一起结算就可能超过额度。因此每次HTTP请求发送前，先在数据库里锁定账号并预留本次费用；余额不够，就不发给模型。拿到有效用量后再结算，释放多余预留。

超时是另一个容易忽略的地方：客户端没收到答案，不等于模型没有工作。我们保留这笔预留，并暂停无法核实费用的账号。明确HTTP错误则保守计入预留上界，原有回退的下一次请求单独记账。换会话、换进程和重启数据库，都不会送回一份新额度。

为了减少低估，输入全部按官方峰时非缓存价计算，输出按峰时价计算。这是软件里的保守费用口径，不是供应商实际账单，可能提前用完。未知模型、网关和媒体请求不沿用未经核对的价格。

这次用合成账号验证：20个并发请求，每个预留1元，只有5个成功，其余15个被拒绝。最终相关回归77项通过；迁移保留原合成用户，重启后已结算和未结算金额都保留。没有运行付费模型。

仍需明确两个边界：账号不等于自然人，多账号需要另一层准入控制；本地通过不等于线上生效。云控制台连接目前报SSL错误，因此新版本还没有上线。发布前还要核对生产版本、执行迁移，并确保旧worker不会继续走未计费路径。
