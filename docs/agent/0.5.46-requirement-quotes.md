# Exact quotes for parallel requirements

The live release gate for candidate `4b61984` rejected the synthetic request
`看看我近期训练和体重，安排今天的饭`. While splitting its goals, the model
reconstructed `看看我近期体重`, which is not a contiguous source quote. The
existing validator correctly rejected it, including the model's repair attempt.
Three targeted calls reproduced this failure; an original-wording control passed.

The task prompt now explains that quotes must be contiguous, omitted words may
not be reconstructed, and independent requirement keys may share a complete
source span. A training-record example illustrates the rule. Source validation,
retry limits, authorization and persistence logic are unchanged.

Validation before remote CI:

- The failing request now succeeds on the first model attempt in all 3 calls,
  retaining training, weight and daily-meal goals. The original control passes.
- Two additional parallel requests preserve exact quotes, both context goals and
  the no-save boundary. One chooses `query/read/answer` for “三餐建议”, rather
  than a daily-meal artifact; output-format behavior remains a separate observation.
  The other chooses `generation/read/daily_meal_plan` as expected. No database was
  connected during these bounded routing diagnostics.
- Full backend regression: 1795 passed, 1 new test failed because an empty quote
  was rejected earlier by the schema than the test expected. After fixing only
  that assertion, all 35 quote/task-state tests pass. Remote CI checks the final
  suite. Invalid reconstructed quotes still fail, while shared source spans
  preserve independently editable requirements.

The original live-gate failure and diagnostic responses are preserved locally.
Finite routing samples do not establish arbitrary-input success, final advice
quality, production behavior, or phone UI acceptance. Those checks are recorded
separately for the final commit.
