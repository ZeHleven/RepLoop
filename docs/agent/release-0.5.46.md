# 0.5.46 候选版本说明

此候选整合 Agent 任务可靠性改动，包含迁移 `0032_agent_queue_position`。候选构建、CI 通过、生产部署是独立状态；本文件不代表已经上线。

## 行为变化

- 以任务契约检查提案的目标、数值与查询范围，并保留多轮待补信息；识别成功还需检查最终业务结果。
- 用户修改尚未确认的计划或餐食需求后，使旧提案失效，避免确认过期版本。
- 续接旧任务、修改查询日期或状态时，保留需求来源，隔离只读查询与写入提案；扩大餐食追问范围前检查当前缺少的信息。
- 同会话同步与异步请求共用持久队列位置；有等待或运行任务时，同步入口返回可重试的忙碌错误。首次并发幂等重放返回原会话，不另存空会话。租约使用数据库时间，降低进程时钟偏差对领取和恢复的影响。
- 待补参数按字段和动作归属保留；首次补齐只有来源明确的纯参数待补条件可解除，混合未知目标继续要求澄清。餐食草稿上限对齐既有30项输入契约，修订仍使旧提案失效。
- 无范围营养列表可直接生成报表；具体日期、餐次及其他限定退回语义执行。两个离散训练日期不再被解释为连续日期区间。
- CI 分开运行单元与数据库测试、完整任务、多轮任务和修订任务评测，保存响应和执行轨迹以便复核。

小程序业务页面没有随此候选重写。API、小程序与后端打包默认版本统一为 `0.5.46`；打包必需项包含 `0032` 和新增 Agent 运行模块。配置模板预算与源码默认值对齐，写入领域开关仍默认关闭。

## 验证与发布要求

候选必须来自干净检出，前后端构建清单应有相同的完整提交 SHA、版本和 `source_dirty=false`。正式构建不能使用局域网验收入口。后端包必须通过内容、体积、ZIP 边界与必需文件检查。

数据库测试会清空业务表，必须使用独立合成测试库。迁移应在该库演练 `upgrade head → downgrade 0023 → upgrade head`，随后运行 CI 中的后端测试和三个确定性任务评测。前端运行提案契约、构建契约、交互补充测试、类型检查和微信构建检查。

真实模型发布门禁需对当前候选完整 SHA 运行 `.github/workflows/daily-meal-live-eval.yml`，按其中的语义路由与两次餐食评测门槛验收；历史提交通过或已见任务回放不能代替该门禁。生产迁移、部署和发布仍需独立执行与核验，步骤见 [CloudBase 部署说明](../../deploy/cloudbase/README.md)。

## 已知边界

合成手机验收已覆盖约定计划与查询的显示、点击导航、退出重开恢复，依据为用户文字确认及对应后端数据核对。它不覆盖本次计划在手机上的确认按钮操作，也没有新增手机截图证据。

旧提案底部点击在桌面开发者工具中曾间歇未进入页面点击处理，手机约定步骤未复现；根因未闭合，保留桌面观察，不记为已修复。配置模板更新不等于现有生产配置已经更新。迁移回退不撤销已经确认的业务写入，也不代表旧应用兼容性已经验证。

营养工具仍最多返回30个有记录日期，快捷路径回退不代表任意日期查询已经完整覆盖。旧版本回退期间若继续写入NULL队列位置记录，再升级后的任务历史语义顺序尚未验证；不能据数据库downgrade成功宣称旧应用回退可用。
